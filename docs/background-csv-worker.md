# CSV 后台导出 worker（R4 实施中）

生产导出不再在 HTTP 服务进程内运行。主服务仅保存有界任务；计划、SQLite 扫描、热数据冻结、冷归档解码、CSV、排序/采样临时库、校验及发布全部在单独的 `export-worker` 进程及其 cgroup 内。

当前提供 Linux cgroup v2 + 本地 SQLite 的严格路径。Windows 等未验证进程组硬限额的平台和未隔离数据库 CPU 的外部 SQL 明确拒绝运行，不自动回退到软限速。没有 worker 时，界面显示配置原因且禁止提交。

## 配额与部署

- 使用 [systemd 示例](../deploy/komari-export-worker.service)。按实际路径修改用户、工作目录、二进制、队列、主实例 cgroup 位置；主服务和 worker 使用同一专用账户，两个 cgroup 必须不同。
- cgroup `cpu.max` 必须不超过 `4000 100000`，CPU burst 为 0，`memory.max` 不超过 128 MiB。worker 进入 cgroup 后才执行初始化、队列读取和规划，所有线程/后代共享同一限制。
- 保守固定为最多 0.04 核，而不是按每任务分配。该值在主实例 0.5/1/2/4/8 有效 CPU 范围内始终低于总算力 10%，并给 1s 窗口周期边界留余量。主实例即使从 8 核降到 0.5 核也不临时超预算；不因空闲自动加速。
- worker 验证指定主实例及可见祖先的 quota/cpuset；运行中持续复验。低于 0.5 核不支持，操作员须先暂停 worker 再下调到该范围外。配额配置失效时停止处理，界面显示不可用，不继续无配额执行。
- 所有任务共享一个独占 worker 锁、全局 8 项/每账户 2 项活动任务上限；确认一个输入单元后切换账户，保持公平。
- 当前每任务冻结输入上限 2 GiB、输出上限 8 GiB，保留至少 256 MiB 磁盘空间；超限明确失败并要求拆分范围。临时输入和文件使用私有目录，不能让其他账户修改。

Docker 部署需要把 worker 放在单独受限容器中，使用同镜像的 `export-worker` 命令，并共享相同绝对数据路径；主实例 cgroup 必须通过只读挂载可验证。在提供并验证具体 Compose 路径前，不声称任意容器拓扑已满足严格限制。

## 格式和恢复

- `mode=raw`：稳定来源/接收顺序长表，逐实际观测，不承诺全局观测时间排序。
- `mode=summary`：与图表相同的统计计划，含输出间隔、真实精度、样本数及缺口。
- `mode=sample30s`：每序列/30 秒槽最早实际观测，时间相同以 ingest/ordinal 决定，磁盘临时库组装宽表，不是平均值。
- 新格式标记 v2，类别仍是 resource/network/latency/all；文件名、状态和下载头均标明版本及模式。不填 mode 的旧请求保持 v1 人类可读列、GiB/KiB/s/MiB 单位及 Ping 分组标题。时间槽固定为 UTC 30 秒，按最早实际观测选样，不再使用跨槽 nearest 连接；显式 mode 默认 v2，消费方必须读取格式版本。
- 计划在后台固定 manifest、水位、存储身份和范围；原始历史不可用时明确失败，不以汇总代替明细。队列等待本身不永久钉住旧归档。
- 原始归档正常只顺序解码一次，热输入复制为私有固定来源，归档由私有硬链接冻结；冻结完成即释放源租约，不让小时级格式化阻塞留存。
- 检查点保存已 fsync 的输出偏移、行数、输入单元及可恢复 SHA256 状态；重启截断未确认尾部。旧单流归档恢复可能重读最后未确认单元，不能重复写入已确认行。
- 发布只有在 flush/fsync/rename/目录 fsync 后才进入 done；48 小时保留从 ready_at 开始。下载仅传输既有文件。
- 到期后删除文件并显示 expired，元数据再保留七天；活动任务优先展示，不会被近期完成记录挤出列表。浏览器用条件 ETag 请求、前台 5 秒/后台 30 秒和错误退避轮询。
- 主服务每 5 秒发布私有授权/存储状态。节点或账户消失、历史 epoch 或存储身份改变会取消任务；状态过期、前台慢读、上报/汇总积压、磁盘不足会自动暂停，条件恢复再继续。删除历史后旧文件下载也会拒绝。
- 逻辑 I/O 默认共享 8 MiB/s，可配置 64 KiB/s–64 MiB/s。这是检查有界输入/输出边界的合作式预算，允许有界突发，不是内核硬 I/O 配额；不替代 cgroup CPU/内存限制。
- 归档新写为带内索引的独立校验 zstd 帧，每帧最多 128 条/约 1 MiB。旧 v1 单流文件原样读取；冻结时做压缩文件校验读取，格式化阶段每个完整输入单元正常只解压一次。恢复必要重读单独计入 decoded/source_scanned，不冒充进度；规划校验 I/O 由同进程预算计量，不计入解码扫描计数。

组件测试和短 E2E不能替代至少两小时的大冷导出及混合负载资格运行；最终支持范围和剩余验收以[补强方案](telemetry-storage-reinforcement-plan.md)第 11 节为准。
