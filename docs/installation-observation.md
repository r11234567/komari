# 配置下发页的实际上报与应用回执

配置下发页原先读取部署模板 `DeploymentProfile.install`，将默认 Linux
路径、服务账号和本地布尔选项显示成节点现状。模板用于生成安装命令，不能
证明实际安装了什么。旧 Agent 协议也没有发送这些实际值。

现在运行中的 Agent 在基础上报中发送 `InstallationObservation`：实际
可执行文件、进程账号、操作系统、安装清单中的服务信息以及白名单本地选项。
账号来自进程查询，不采用清单里的目标账号。密码、令牌及 Cloudflare 密钥
不进入此消息。此消息仅提供信息，不证明 root 权限或授权任何 Host 操作。

后端分别记录 Agent 采集时间和面板接收时间，仅通过管理员
`DeploymentService.GetDeployment` 返回观测，不加入公开节点信息。
观测保存在内存；面板重启后等待 Agent 的下一次基础上报。旧 Agent 没有
这些字段时，页面显示“未上报”，不会拿部署模板、Linux 路径或默认 false 补值。
两套前端共用同一组件。Windows 等不支持 Host 操作的平台会显示平台能力说明；
普通监控配置通过独立通道工作，不依赖 Linux 特权基线。

查询命令基于实际上报的可执行文件和清单路径生成，Windows 使用 PowerShell
调用语法，Unix 使用 shell 引号。没有路径上报时不生成推测命令。
本地自动更新 flag 也不代表守护进程有自更新能力，当前明确上报不支持 daemon 自更新。

## 普通配置与冲突恢复

普通配置表单只提交运行时白名单字段；“从网卡获取 IP”使用
`RuntimeConfig.get_ip_addr_from_nic`，不回写安装模板。状态每五秒刷新一次，
保留未保存草稿，并拒绝旧版本或旧时间的轮询结果。其他管理员修改版本后，
需要重新打开窗口，防止旧草稿覆盖新配置。

`same runtime revision has different content` 表示本地快照和面板同版本
内容不一致。保留本地快照和拒绝回执；检查表单后“保存并下发普通配置”会
创建新版本，由 Agent 正常校验、持久化并确认。无需删节点、删快照或重新登录。
仅凭基础上报里的磁盘版本号不再推进 `applied_revision` 或覆盖拒绝结果；
只有配置应用回执可确认成功。

## 验证与升级范围

协议、Agent、后端、Web 必须使用同一新增协议提交。旧 Agent 仍可监控和应用
普通配置，但实际安装字段要更新到包含本次上报实现的 Agent 才能显示。
本改动不自动发布正式版或移动 tag。

CI 覆盖 Linux/Windows 实际进程账号、可选 false、敏感字段不泄漏、管理员
查询链路、公开接口隔离、同版本拒绝不被数字上报覆盖、新版本恢复和两套
前端构建。完整构建和测试日志保留 30 天，失败时也上传。
