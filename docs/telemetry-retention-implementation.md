# 遥测内容与留存方案：第一批实现与验证

日期：2026-11-13。关联 [综合方案](telemetry-content-retention-plan.md)、[主库收敛方案](telemetry-storage-upstream-alignment.md)、[补强方案](telemetry-storage-reinforcement-plan.md)。本批附加到 SQLite 重构 PR；不代表整份方案或容量验收已经完成。

## 已接入的生产路径

1. 统一为 `10s → 1m → 5m → 30m → 1h → 2h → 6h → 12h → 1d`。对应年龄边界为 1h、1d、2d、7d、15d、60d、180d、365d；终端日桶仍服从指标自身到期时间。
2. 新的在线输入仅写最细基础层，父层接近子层到期时才生成。父统计与子输入交接标记同事务提交，未交接不能删除。旧 v1 和部分完成 5m→15m 的 v2 输入保留独立升级路径。
3. 调度器通过现有索引读取最早待交接键，持久保存下次到期时间。空闲层级不再被每分钟的封口任务无条件唤醒。
4. 查询在同一快照里组合不同来源精度，按 owner 流式读取；普通标量图不保留它用不到的分布，Ping 统计卡保留合并分布。边界证据支持到日桶，不用插值拆桶凑点。
5. 第一方图表与后端、summary CSV 默认使用 600 点预算，优先约 360 个真实格。45d 等窗口允许 540 点，75d 使用 300 点。显式较小预算仍是上限。
6. 在线精确边缘读取窗口与热明细安全留存分开。运行时默认分别为 15 分钟和一天；`metric_hot_retention_minutes` 可配置，必须不短于在线窗口。增大安全留存不会允许前台扫描全天原始点。
7. 旧库导入尽量按数据年龄直接形成保留层；新的策略完成标记使旧迁移结果也能收敛。空窗口不提交逐窗口进度，也不执行无意义的归档/清理；有输入的窗口仍保留可恢复检查点。

## 本地数据库验证

- 生产构建与显式旧格式夹具构建分别运行完整存储 race 套件。
- 独立原始观测矩阵覆盖在线写入/迁移、迟到、晋升、清理、重启及关闭归档根之后的查询，包含半年、一年及跨年窗口。
- 到期前 1ns、到期、到期后 1ns 检查每一层的样本数/和；检查部分完成旧 15m 交接、不同 population、全丢包、非嵌套旧层、同时间首末等兼容情况。
- PostgreSQL 17、MySQL 8.4、MariaDB 11.4 与 SQLite 的实际驱动，生产/旧夹具两种构建都打乱顺序重复执行；DSN 缺失的 SKIP 不计作验证。
- 实际自动升级、受限启动与旧表退役后的启动另行验证。
- 整套线上合成曲线夹具先在本地运行生产迁移，再逐点核对 CPU/Ping。使用 `KOMARI_TELEMETRY_MIGRATION_CURVE_FIXTURE=1 go test -race ./scripts/ci/migration-fixture -run TestSyntheticMigrationCurveFixture -v`。

真实事故输入仅在本地的独立 SQLite backup 副本上检查。表清单、DDL、字段、索引、各层行数/载荷、dbstat 页面分布、完整性、前后统计及原始分位排名核验的私有产物不提交仓库。本地真实容量结果也不混入可分享的合成报告。

## 线上 E2E 与可审核产物

工作流使用 `database_only=true, skip_csv=true, export_qualification=false`。仅数据库升级、曲线、账本、归档与恢复；不加入 TOTP、终端或 Agent 升级场景。

表由当前生产代码创建，CPU、Ping、计数器和增量全部来自公式，最长 400 天。近期密集上报，旧时期至少填充对应保留格；Ping 包含真实的失败表示 `-1`。线上任务不接受本地数据库路径、备份、真实记录或私有报告作为输入。

`storage-curves.cjs` 逐点比较 HTTP QueryMetrics 与独立 JavaScript 原始观测分组参考。起止使用实际执行时间，避免把迁移前固定的 1h 窗口错误当成仍处于最新 1h 留存内。覆盖 1h/6h/12h/1d/7d/15d，此后每 15 天到 390 天，另有 365d、400d。

产物包括：

| 文件 | 内容 |
| --- | --- |
| `storage-curve-oracle.json` | 明确标注为合成来源的原始观测及夹具网格 |
| `storage-curve-http.json` | 每个窗口的请求、实际响应与逐桶原始参考 |
| `storage-curve-<hours>h.png` | 运行构建后真正实例页面的曲线截图 |
| `storage-curve-screenshots.json` | 每张截图对应的 UI 请求与响应；等待匹配窗口、节点、指标、预算与渲染完成 |
| `storage-synthetic-table-audit.json` | 合成 SQL 的结构、完整索引列、各层数量/载荷、编码、页面占用与索引查询计划 |

截图不使用拦截网络、替换响应或注入 React 数据。365d 非标准快捷窗口由 HTTP 验证；其余快捷窗口及最后的 400d 留存窗口截图。确认工作流在提交 SHA 上启动后停止查看，不轮询结果。

## 尚未完成的后续批次

- 在线统计主表按上游思路进一步收敛：独立可投影标量/分布、紧凑二进制编码、常量人口恢复，以及归档 owner/收据和逐桶重复元数据的回收。不能把这批留存改动当成该项已经完成。
- 停机积压/迟到在线输入直接到年龄对应层，避免恢复期间先写完所有中间层；必须证明混合年龄与现有 owner 的兼容性。
- 一天热明细下的完整事故库重新迁移、SQL/索引/WAL/归档分项容量与交接峰值验收；容量目标仍需实际生产格式证明。
- 冷 CSV 的帧级时间/序列选择、清单字节与内存预算；大窗口不能只扩大工作单元上限。三种导出及 CPU 配额重新长测。
- 本批线上 CI/E2E 结果与实际截图由工作流产物给出；启动不等于通过。最终总验收和实机 24h 观察仍单独记录。
