# Dev 版真实探针验收

适用环境：Debian 探针、Debian Docker 面板、Nginx 反向代理。
本轮重点是 WebSSH 冷启动、交互授权边界、文件传输及上报恢复。

## 准备

- 选一台之前连接快、一台之前连接慢的机器，优先包含双栈机器。
- 记录面板、Agent 的完整版本和节点名称。WebSSH 拨号修复在 Agent 中，
  只更新面板无法验证那部分修复；测试时同时使用本轮 Agent dev。
- 保留独立 SSH 通道。在一个专用测试用户和临时目录内操作，先不碰业务文件。
- 观察正常运行基线：连续上报、面板 CPU/内存、探针 CPU/内存。
- 每个问题记录：浏览器点击时间、节点、当时阶段、耗时、精确报错，以及同时间段
  的浏览器 Network、面板容器日志和 Agent 日志。不要提交 Cookie、凭据或终端敏感内容。

## 1. 冷启动与首屏输出——先测

1. 重启测试 Agent，使它重新连接面板；等节点恢复在线，再首次打开 WebSSH。
   另外记录一次 Agent 尚在重连时点击连接的行为。浏览器刷新不等于重新测 Agent 冷启动。
2. 快、慢机器各重复 5 次，记录从点击到 Agent 附着、到首字输出的时间。
3. 观察界面是否持续显示创建／等待探针／等待输出及耗时；黑屏不能被当成已经连上。
4. 输入 `id; pwd; tty`：字符应即时显示，回车能执行，身份应是选择的本机用户。
5. 对照热启动和冷启动。慢机应有明确耗时定位；不能依靠锁定后再解锁才显示旧结果。

预期：快机无明显退化；慢机不再经历每个不可达 IP 的整段串行超时。真正附着或有输出前
不可输入，等待期间有状态反馈。若仍慢，区分“没有附着”和“已附着但 shell 没有输出”。

## 2. Nginx 流式响应、交互和恢复

- 连接后空闲 1–2 分钟再输入；同时用 `sleep 20; printf 'done\n'` 检查安静期间的状态。
- 执行 `seq 1 1000`，检查输出持续显示、顺序正确，不在结束后一次性涌出。
- 用 `sleep 60` 后按 Ctrl+C；测试 Tab 补全、方向键历史、中文输入／粘贴和窗口缩放。
- 在测试节点执行 `seq 1 200000`，输出过程中按 Ctrl+C、缩放窗口，再锁定工作区。
  先记录普通网络表现，再通过浏览器开发工具限速复测；不要拿业务日志或敏感文件造流量。
  输入不能因为输出积压一直排队，锁定后不能继续执行旧输入。若达到缓冲上限，应明确失败
  关闭，不能假装完整成功；本轮没有承诺无限输出缓存。
- 两台机器各开两个终端标签，切换和关闭其中一个；其他标签不能串输入或被误关。
- 短暂断开测试浏览器网络后恢复；再分别重启测试 Agent 和面板容器。

预期：无持续转圈或假在线；恢复行为有提示、无重复输出／重复执行旧输入。
旧授权失效后不得自动恢复可操作终端。输出突发时记录 Nginx 的流式请求时间线，
不要为“试试看”盲目放宽鉴权或 Origin 设置。

## 3. 工作区锁定、退出与节点隔离

- 手动锁定，尝试输入、粘贴、上传和启动执行任务：都应被拒绝，进行中的受控操作应停止。
- 空闲约 3 分钟测试自动锁定；再持续操作到约 30 分钟测试绝对期限。
  心跳、上报、历史查询不能自行延长交互授权。
- 同一节点打开第二窗口，检查锁定状态同步；锁定 A 节点不能误锁 B 节点。
- 面板退出登录后，用原标签页继续操作；再重新登录并验证解锁。
- 在另一个管理员窗口撤销测试设备或关闭远控能力，检查原终端和传输是否停止。

预期：锁定立即生效；恢复操作需要有效的新授权。残留界面、旧标签和自动重连不能绕过锁定。

## 4. 本机用户与文件权限

- 选择普通用户进入终端，核对 `id`。尝试访问该用户无权访问的目录，应明确失败。
- 未在机器本地允许 root 时，面板不能自行开启 root 工作区。
- 在临时目录创建／重命名／删除文件和目录；测试空格、中文、较长文件名。
- 分别传输一个小文件和一个适量的大文件，上传下载后用 `sha256sum` 核对。
- 测试同名文件覆盖确认、目录递归确认、传输取消，以及中途锁定／断网。

预期：文件权限与选定用户一致；取消或失败有明确状态，无静默覆盖、假成功或越权继续传输。

## 5. 节点上报、流量和配置

- 观察 CPU、内存、磁盘、网速与 Ping 是否持续更新；与本机 `uptime`、`free -m`、`df -h`
  做数量级核对。不能把容器视图与宿主机视图直接当成同一统计口径。
- 重启探针、短暂断网后检查上线／离线状态、历史空档和恢复后数据；重复开关页面不能增加上报。
- 在测试节点校准流量后刷新、切换页面、重启面板；核对额度、重置日期／时区和显示值保持一致。
- 在节点编辑器填写非法流量额度，应拒绝保存；其他字段不应被一起部分写入，列表仍能正常读取。
- 在测试机进行一次实际配置变更，核对期望值、机器观察值、已应用值及回执；保留本机审批要求。

预期：重启／重连不造成异常流量尖峰、重复累计或失控重试；配置失败不能显示为已应用。

## 建议顺序与停止条件

按 1 → 3 → 2 → 4 → 5 执行。先确认慢连接和权限失效，再做批量节点验证。
一旦出现锁定后仍可控制、普通用户越权、旧输入重复执行、业务文件被意外覆盖，
立即停止扩大测试并保留现场；一般性能问题记录对照数据后继续排查。
